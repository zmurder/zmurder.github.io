SSH隧道

发表于 2026-10-18 分类于 Linux 阅读次数：

1 背景

现有三台机器，网络关系如下：

机器 地址 SSH 端口 说明
本地 PC - - 开发机（Windows）
服务器 10.0.206.124 32354 远程 Linux 服务器
台架 10.13.193.69 31936 测试台架，运行 SSH 服务

连通性：

  • 本地 PC → 服务器：可以，ssh -p 32354 root@10.0.206.124
  • 本地 PC → 台架：可以，ssh -p 31936 <台架用户名>@10.13.193.69
  • 服务器 → 台架：不可以，服务器路由不到台架所在的网段

现在的需求是：在服务器上操作台架。台架不能被服务器直接访问，怎么办？

2 解决方案

核心思路：在本地 PC 上建立一条 SSH 远程转发隧道，把服务器的 54321 端口映射到台架的 31936 端口。之后在服务器上访问自己的 127.0.0.1:54321，流量就会经本地 PC 中转，最终到达台架。

2.1 在本地 PC 上建立隧道

命令保持运行，隧道就保持有效。各参数作用如下：

参数 作用
-N 不执行远程命令，只做端口转发
-o ServerAliveInterval=15 每 15 秒向服务器发送一次保活探测
-o ServerAliveCountMax=8 连续 8 次探测无响应就断开（约 120 秒）
-R 54321:10.13.193.69:31936 让服务器监听 54321，流量经本地 PC 转发到台架的 31936
-p 32354 登录服务器的 SSH 端口
-i "C:\Users\username\.ssh\id_rsa_6v_a3" 登录服务器使用的私钥文件

注意 -p 是小写，指定的是 SSH 端口；scp 中对应的参数是大写 -P。私钥路径不要漏掉 .ssh 前面的反斜杠，常见错误是写成 C:\Users\username.ssh\...，这样指向的是另一个目录。

3 原理：远程转发 -R

3.1 数据流向

以本次命令 -R 54321:10.13.193.69:31936 为例，一条连接完整经过以下几步：

从各方的视角看：

  • 服务器只是在访问自己的 127.0.0.1:54321，它并不需要知道台架的存在；
  • 台架看到的连接来自本地 PC；
  • 本地 PC 是中间的跳板，负责把两边接起来。

3.2 保活参数

ServerAliveInterval 和 ServerAliveCountMax 是客户端的探活设置：

  • ServerAliveInterval=15：每 15 秒向服务器发送一次保活探测；
  • ServerAliveCountMax=8：连续 8 次探测没有响应，就认为连接已经断开并退出。

也就是最多约 15 × 8 = 120 秒无响应后，ssh 会主动结束。

为什么要设置：本地 PC 和服务器之间通常隔着 NAT 或防火墙，长时间没有数据的 TCP 连接会被中间设备悄悄回收，表现就是“隧道看起来还在，实际已经不通了”。定时发送保活报文可以让连接保持活跃，也能让 ssh 及时发现死连接。

注意区分：ServerAlive* 是客户端探活，对应的服务端参数是 ClientAlive*。

3.4 常见的失败原因

  • remote port forwarding failed for listen port 54321：服务器上 54321 已被占用，或者 sshd 配置了 AllowTcpForwarding no；
  • 服务器上连 54321 被拒绝：本地 PC 的 ssh 进程已经退出，或隧道没有建立成功（用 ssh -v 可以看到 remote forward success for: listen 54321）；
  • 连上了但马上断开：本地 PC 到台架不通，或台架防火墙拦截。可以先在本地 PC 上直接 ssh -p 31936 <台架用户名>@10.13.193.69 验证；
  • bind: Permission denied：非 root 用户绑定 1024 以下端口需要权限，换一个高位端口即可。

4 SSH 的其他转发方式与应用场景

SSH 隧道本质是把其他 TCP 连接封装在一条已经建立的 SSH 连接里传输。对外看只是普通的 SSH 流量，里面跑的可以是 SSH、HTTP、数据库等任意 TCP 协议。除了上面用到的 -R，SSH 还提供 -L 和 -D 两种转发方式。

一句话概括：-L 是“把远端网络拉到本地”。

语法：

这条命令在本地 127.0.0.1:1080 起了一个 SOCKS5 代理。任何把流量交给这个代理的程序，其连接都会经 SSH 服务器发出，而目标地址由程序在运行时通过 SOCKS 协议告诉代理，不需要在命令行里写死 host:hostport。

使用方式：

浏览器中把代理设置为 SOCKS5、地址 127.0.0.1、端口 1080 即可。

与 -L 的区别：-L 一次只能把本地一个端口映射到一个固定目标；-D 只开一个端口，却能代理到服务器能访问的任意地址，目标由每个连接动态指定。可以把它理解为“目标可变的 -L”。

OpenSSH 7.6 及以上版本还支持远程动态转发 -R 1080（不带目标地址），在远端开一个 SOCKS 代理，效果与 -D 镜像。

4.3 三者的区别与联系

对比项 -L 本地转发 -R 远程转发 -D 动态转发
监听端 本地 远端（SSH 服务器） 本地
目标地址 命令行写死 命令行写死 不写死，由 SOCKS 请求决定
目标由谁连接 服务器 本地 服务器
承载协议 任意 TCP 任意 TCP SOCKS5 代理
典型场景 通过跳板机访问内网服务 把本地/内网服务暴露给远端 让程序整体走服务器的网络出口
一句话 把远端拉到本地 把本地推到远端 本地开一个能去远端的代理

三者的联系：

  • 底层都复用同一条 SSH 连接，靠 SSH 的通道（channel）多路复用同时承载多个转发；
  • -L 和 -R 是一对镜像：同一组映射，在哪一端执行决定了监听端和目标端的角色；
  • -D 可以看作 -L 的动态版本：只监听一个端口，但目标由 SOCKS 协议在运行时决定，一个端口服务所有地址；
  • 三个参数可以同时出现在一条命令里，也可以重复使用（例如同时开多条 -L 或 -R）。

4.4 如何选择

需求 选择
服务器要访问本地 PC 或本地 PC 能到达的地址 -R
本地要访问服务器或服务器内网的服务 -L
让浏览器、程序整体走服务器的网络出口 -D

回到本次场景：台架的服务地址是固定的 10.13.193.69:31936，所以用 -R 最直接。如果希望服务器能访问“本地 PC 能到达的任意地址”，则可以改用远程动态转发 -R 1080，在服务器上把它当作 SOCKS5 代理使用。

5.3 安全提醒

  • 隧道一旦建立，能访问服务器 54321 的人就等价于能访问台架，注意服务器上的账户权限和访问控制；
  • 不要随意开启 GatewayPorts yes，默认只监听回环地址是最安全的；
  • 使用密钥认证，不要图省事使用弱密码；
  • 隧道只应该开给需要的端口，转发范围越小越好。
